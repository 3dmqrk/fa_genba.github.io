MELSEC-QシリーズからMELSEC iQ-Rシリーズへ更新するとき、最初に困るのが「何から確認すればいいのか」です。

CPUやI/Oの後継形名だけならマイグレーションツールで探せますが、実際の更新ではそれだけでは足りません。
**外部配線、入力電流、ON/OFF条件、トランジスタ出力の方式や漏れ電流、バッファメモリ、通信、プログラム変換**など、新旧で仕様が変わる部分があります。

この記事では、Q→iQ-R更新をするときに私ならどの順番で確認するかを整理します。

本記事は公開されている資料をもとにした一般的な技術情報です。実際の更新では、対象機種の最新マニュアル・技術資料を確認してください。

## 結論

Q→iQ-R更新では、次の順番で確認すると整理しやすいです。

<div class="mermaid-container" style="width: 30%; --mermaid-zoom: 0.9693659832451089;">
  <pre><code class="language-mermaid">flowchart TD
  A[既設Qシステムを確認] --&gt; B[マイグレーションツールで候補選定]
  B --&gt; C[L08489 移行ガイドで仕様差を確認]
  C --&gt; D{そのまま置換できるか}
  D --&gt;|できる| E[Rシリーズの構成を確定]
  D --&gt;|難しい| F[RQ増設ベースや代替方法を検討]
  F --&gt; E
  E --&gt; G[GX Works2で移行前確認]
  G --&gt; H[GX Works3へプロジェクト移行]
  H --&gt; I[変換結果・通信・特殊ユニットを確認]
  I --&gt; J[実機でI/Oと設備動作を確認]</code></pre>
</div>

ポイントは、**「後継形名が見つかった」＝「そのまま置き換えられる」ではない**ことです。

Q→iQ-R更新は、単なる型式置換ではなく、**既設システムをRシリーズでどう再構成するかを考える作業**として進めた方が分かりやすいです。

## 1. 既設構成を確認する

最初にCPUだけではなく、PLC一式の構成を確認します。

```text
CPU
電源
基本ベース・増設ベース
デジタルI/O
アナログI/O
位置決め・高速カウンタなどの特殊ユニット
Ethernet・CC-Link・MELSECNET/Hなどの通信ユニット
GOT
増設ケーブル
```

プロジェクトが手元にある場合でも、実機と一致しているとは限りません。

GX Works2のシステムモニタで実装ユニットを確認しておくと、後のプロジェクト移行でも役立ちます。

### 更新前はプログラム以外もバックアップする

更新前はPLCプログラムだけでなく、設備を復元するために必要な情報をできるだけ残しておきます。

```text
PLCプログラム
PCパラメータ
I/O割付
ネットワークパラメータ
インテリジェント機能ユニット設定
保持が必要なデータ
GOTプロジェクト
上位PC・SCADA側の通信設定
```

古い設備ほど、保管されているプロジェクトと実機が一致しているとは限りません。可能であれば更新前にオンライン接続し、実機から最新データを読み出しておきます。

## 2. 過去にA→Q更新している設備はリニューアルツールも確認する

現在Qシリーズが付いていても、最初からQシリーズだったとは限りません。

古い設備では、AシリーズからQシリーズへ更新したときに、既設配線を残すためのリニューアルツールや変換アダプタが使われている場合があります。

<div class="mermaid-container" style="width: 73%; --mermaid-zoom: 1.8;">
  <pre><code class="language-mermaid">flowchart LR
  A[MELSEC-A] --&gt;|過去の更新| B[MELSEC-Q]
  B --&gt;|今回の更新| C[MELSEC iQ-R]
  D[既設配線] --&gt; E[変換アダプタ]
  E --&gt; B
  E -. Rでも使用できるか確認 .-&gt; C</code></pre>
</div>

この場合はPLCユニットだけでなく、**現在使用している変換アダプタの形名とiQ-Rでの使用可否**まで確認します。

既設の変換アダプタを流用できれば配線改造を減らせる場合がありますが、使用可否はアダプタごとに確認が必要です。

## 3. マイグレーションツールで置換候補を探す

既設構成が分かったら、三菱電機のマイグレーションツールでiQ-R側の候補を確認します。

[MELSEC-Qシリーズ ⇒ MELSEC iQ-Rシリーズ マイグレーションツール](https://www.mitsubishielectric.co.jp/fa/products/cnt/plcq/ex/select/q2rmigration/q2rmigration.html)

ここではCPUだけでなく、**電源・ベース・I/O・特殊ユニットまで一式で確認**します。

ただし、マイグレーションツールは「次に確認する機種を探すもの」と考えた方がよいです。

候補が出たら、次に移行ガイドで新旧の仕様差を確認します。

## 4. L08489で新旧の仕様差を見る

Q→iQ-R更新で特に便利なのが、三菱電機の移行ガイドです。

[MELSEC-QシリーズからMELSEC iQ-Rシリーズへの移行ガイド L08489](https://dl.mitsubishielectric.co.jp/dl/fa/document/catalog/plcq/l08489/l08489g.pdf)

CPU、I/O、アナログ、ネットワーク、位置決め、情報ユニット、プロジェクト移行などが1冊にまとまっています。

確認するときは、単に「Qのこの形名はRの何になるか」だけではなく、次の項目まで見ます。

```text
外部配線
スロット数
入出力占有点数
電気的仕様
入出力信号
バッファメモリ
性能仕様
機能仕様
```

### デジタルI/Oは特に電気的仕様を見る

デジタルI/Oは、点数と端子形状が合っていれば終わり、ではありません。

例えば入力ユニットでは、

```text
定格入力電圧
定格入力電流
ON電圧 / ON電流
OFF電圧 / OFF電流
コモン方式
応答時間
```

を確認します。

QシリーズとiQ-Rシリーズでは、対応するユニットでも入力電流やON/OFF条件が異なる場合があります。

そのため、既設センサの出力仕様によっては「後継ユニットだから大丈夫」と判断せず、センサ側のON時・OFF時の条件まで含めて確認した方が安全です。

出力ユニットも同様です。

```text
シンク出力 / ソース出力
1点あたりの定格負荷電流
1コモンあたりの許容電流
最大突入電流
OFF時漏れ電流
ON時最大電圧降下
保護機能
コモン方式
```

特にトランジスタ出力では、**シンク/ソースの違い、負荷電流、OFF時漏れ電流**を見落とすと、既設負荷との組み合わせで問題になる可能性があります。

つまりデジタルI/Oも、

点数が同じだから置換可能

ではなく、

既設のセンサ・負荷を新しいI/Oユニットで正しくON/OFFできるか

まで確認する必要があります。

## 6. 盤に入るかも確認する

電気仕様とプログラムだけ確認して、最後に困ることがあるのが盤内寸法です。

QシリーズとiQ-Rシリーズではユニットの外形寸法が異なるため、既設盤では奥行き方向などの確認も必要です。

<div class="mermaid-container" style="width: 70%; --mermaid-zoom: 1;">
  <pre><code class="language-mermaid">flowchart LR
  A[電気仕様 OK] --&gt; B[プログラム移行 OK]
  B --&gt; C{盤内に収まるか}
  C --&gt;|Yes| D[次へ]
  C --&gt;|No| E[盤改造・配置変更を検討]</code></pre>
</div>

確認するのはユニット寸法だけではありません。

```text
盤扉との干渉
配線ダクトとの距離
コネクタ・ケーブルの曲げスペース
増設構成の全長
```

**電気的に置換できても、物理的に置換できるとは限りません。**

## 7. 特殊ユニットはバッファメモリまで確認する

アナログ、位置決め、通信などの特殊ユニットでは、既存プログラムからどのようにアクセスしているかも確認します。

例えば、

```text
FROM
TO
U□\G□
```

などを検索し、バッファメモリへ直接アクセスしている箇所を洗い出します。

<div class="mermaid-container" style="width: 70%; --mermaid-zoom: 1;">
  <pre><code class="language-mermaid">flowchart LR
  A[特殊ユニットをRへ置換] --&gt; B[新旧仕様を比較]
  B --&gt; C[既設プログラムを検索]
  C --&gt; D{バッファメモリへ直接アクセス?}
  D --&gt;|Yes| E[アドレス・機能を照合]
  D --&gt;|No| F[パラメータ・入出力信号を確認]</code></pre>
</div>

新旧ユニットでバッファメモリアドレスや機能が変わっていれば、プログラム側の修正が必要になります。

ユニットをRへ置き換えるだけではなく、**そのユニットをプログラムからどう使っているか**まで確認するのがポイントです。

## 8. 直接置換できないユニットはシステム構成から考える

Qシリーズには、iQ-Rで単純な1対1置換にならないユニットもあります。

その場合は次のように考えます。

<div class="mermaid-container" style="width: 70%; --mermaid-zoom: 1;">
  <pre><code class="language-mermaid">flowchart LR
  A[直接置換できない] --&gt; B{R側で代替機能があるか}
  B --&gt;|ある| C[Rユニット・別機能で代替]
  B --&gt;|ない・改造が大きい| D[RQ増設ベースを確認]
  D --&gt; E[対応するQユニットを継続使用]</code></pre>
</div>

RQ増設ベースを使用すると、対応するQシリーズユニットをRCPUのシステムで継続使用できる場合があります。

特殊ユニットまで一度に全交換すると改造範囲が大きくなる設備では、この方法も選択肢になります。

## 9. リモートI/Oはネットワークごと変わる場合がある

Q→R更新では、すべてのネットワーク機能が同じ方式のまま1対1で置換できるとは限りません。

例えばQシリーズのMELSECNET/HリモートI/O構成をRシリーズへ更新する場合、設備によってはCC-Link IEフィールドネットワークとRシリーズのリモートヘッドユニットを使う構成への更新を検討することになります。

<div class="mermaid-container" style="width: 70%; --mermaid-zoom: 1;">
  <pre><code class="language-mermaid">flowchart LR
  A[Qシリーズ&lt;br/&gt;MELSECNET/HリモートI/O] --&gt; B[ネットワーク更新]
  B --&gt; C[iQ-R&lt;br/&gt;CC-Link IEフィールド]
  C --&gt; D[Rシリーズ&lt;br/&gt;リモートヘッド構成]</code></pre>
</div>

このような更新では、ユニットだけではなく、

```text
ネットワーク配線
局構成
局番
リンクデバイス
RX / RY
RWr / RWw
上位局・他局との接続
```

まで影響範囲になります。

そのためネットワーク関連は、**「Qのネットワークユニットの後継は何か」ではなく、「既設ネットワーク全体をRでどう構成するか」**で考えた方がよいです。

## 10. ハード構成が決まったらプロジェクトを移行する

ハードウェア側の構成が決まったら、GX Works2のプロジェクトをGX Works3へ移行します。

移行ガイドでは、QCPUに格納されているプロジェクトについて、おおむね次の流れで説明されています。

<div class="mermaid-container" style="width: 38%; --mermaid-zoom: 0.9377969366942832;">
  <pre><code class="language-mermaid">flowchart TD
  A[GX Works2でQCPUから読出し] --&gt; B[I/O割付・パラメータ確認]
  B --&gt; C{QnUCPU形式か}
  C --&gt;|No| D[GX Works2でQnUCPUへPCタイプ変更]
  C --&gt;|Yes| E[GX Works3でGX Works2形式を開く]
  D --&gt; E
  E --&gt; F[変換結果を確認]
  F --&gt; G[RCPUへ書込み]</code></pre>
</div>

GX Works3では、

```text
プロジェクト
  → 他形式ファイルを開く
    → GX Works2形式
      → プロジェクトを開く
```

からプロジェクトを読み込みます。

古いQCPUの場合は、その前にGX Works2でQnUCPUへPCタイプ変更する工程が入る場合があります。

## 6. 「変換できた」で終わらせない

GX Works3でプロジェクトが開けても、それだけで移行完了ではありません。

特に確認したいのは、

```text
対応していない命令
特殊ユニットのバッファメモリ
ネットワークパラメータ
デバイス・メモリ関連
QとRで動作が異なる機能
```

です。

例えばユニットによっては、外部配線や入出力信号はそのままでも、バッファメモリアドレスが変わる場合があります。

プログラム変換後はコンパイルエラーだけを見るのではなく、**L08489の該当ユニットの仕様差と照合する**のが重要です。

## 7. 最後は実機で確認する

最後は設備として動作確認します。

```text
□ 入力がすべて正常に入るか
□ 出力負荷が正常にON/OFFするか
□ アナログ値に差がないか
□ Ethernet・CC-Linkなどが正常に通信するか
□ GOTが正常に接続できるか
□ 上位PC・SCADAと通信できるか
□ 起動・停止・異常復旧動作に問題がないか
□ 停電保持が必要なデータが維持されるか
```

CPUがRUNになったことではなく、**設備として従来と同じ動作ができること**を確認して更新完了です。

## よく使う資料

| 確認したいこと | 資料・ツール |
| --- | --- |
| Q→Rの候補形名 | Q→iQ-R マイグレーションツール |
| 新旧の仕様差 | MELSEC-Q → MELSEC iQ-R 移行ガイド L08489 |
| R側I/Oの詳細仕様 | MELSEC iQ-R 入出力ユニットユーザーズマニュアル SH-081246 |
| Rシリーズの構成条件 | MELSEC iQ-R ユニット構成マニュアル SH-081222 |
| プロジェクト移行 | GX Works2 / GX Works3 |

私はまず、

```text
マイグレーションツール
        ↓
L08489 移行ガイド
        ↓
気になるユニットだけ個別マニュアル
```

という順番で調べるのが分かりやすいと思います。

## まとめ

MELSEC-QからMELSEC iQ-Rへの更新は、単純な後継機種への交換ではありません。

重要なのは、**既設設備が何を要求しているかを把握し、それをRシリーズでどう実現するか**です。

特に注意したいのは、

- デジタルI/Oの入力電流、ON/OFF条件、シンク/ソース、漏れ電流などの電気的仕様
- A→Q更新時のリニューアルツールや変換アダプタ
- Q/Rで異なる外形寸法や盤内スペース
- 特殊ユニットのバッファメモリ
- RQ増設ベースによるQユニット継続使用
- リモートI/Oなどネットワーク方式そのものの更新
- GX Works3変換後に残る旧Qシリーズの記述

です。

**「後継形名を探す」のではなく、「既設システムをRで再構成する」。**

この考え方で進めると、Q→iQ-R更新時の確認漏れを減らしやすくなります。
